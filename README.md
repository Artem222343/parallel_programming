## 1. Цель работы
Разработать параллельную программу перемножения квадратных матриц с использованием технологии MPI (Message Passing Interface) для архитектур с разделенной памятью. Провести серию экспериментов, оценить ускорение и сравнить поведение MPI с технологией OpenMP (из ЛР №2).

## 2. Описание реализации
Программа реализована на C++ с применением библиотеки `<mpi.h>`. Вычисления распределяются по модели «Master-Worker» (Главный-Рабочие):
1. **Master-процесс (ранг 0)** читает матрицы $A$ и $B$ из файлов.
2. Процесс 0 рассылает всем остальным процессам размер задачи $N$ (через `MPI_Bcast`).
3. Матрица $B$ рассылается целиком всем процессам через `MPI_Bcast`, так как для вычисления любой строки результирующей матрицы требуются все столбцы $B$.
4. Матрица $A$ "нарезается" на блоки строк. Функция `MPI_Scatterv` распределяет эти блоки между процессами пропорционально, с учетом того, что $N$ может не делиться нацело на количество процессов.
5. Каждый процесс производит умножение своих строк матрицы $A$ на матрицу $B$ (используется кэш-оптимизированный порядок циклов `i-k-j`).
6. Функция `MPI_Gatherv` собирает локальные результаты со всех процессов обратно в результирующую матрицу $C$ на процессе 0.

Время измеряется с помощью функции `MPI_Wtime()`, охватывающей как этап пересылки данных (Scatter/Bcast), так и этап вычислений и сборки результатов (Gather).

## 3. Условия экспериментов
* **Оборудование:** Процессор (6 физических ядер, 12 потоков).
* **Параметры компилятора:** `mpicxx -O3 matrix_mpi.cpp -o matrix_mpi`.

* **Количество процессов:** 1, 2, 4, 6, 8, 12.

### 4.2. Анализ результатов
* На объеме $N=2000$ при 6 процессах (максимум физических ядер) достигнуто ускорение **~2.07x**.
* **Сравнение с OpenMP:** MPI-версия работает чуть медленнее версии на OpenMP (из ЛР №2). Это ожидаемое поведение: в OpenMP потоки читают данные напрямую из общей оперативной памяти. В MPI происходит явное копирование данных (создание буферов, передача через `MPI_Bcast` и `MPI_Scatterv`), что создает накладные расходы (overhead).
* На малых матрицах ($N=200$) запуск на 8-12 процессах даже увеличивает время выполнения по сравнению с 6 процессами. Это происходит потому, что время на передачу сообщений между процессами превышает время самих математических вычислений.
