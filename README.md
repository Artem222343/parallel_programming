## 1. Цель работы
Реализовать алгоритм перемножения квадратных матриц с использованием графического ускорителя (GPU) по технологии NVIDIA CUDA. Провести экспериментальное исследование производительности в зависимости от размера матриц и конфигурации сетки (grid) / блоков (block) потоков. Сравнить эффективность GPU-вычислений с реализациями на CPU (OpenMP, MPI).

## 2. Описание реализации
Программа реализована на C++ с использованием расширений CUDA (файл `.cu`). 
Для распараллеливания используется глобальная память видеокарты:
1. Выделяется память на устройстве с помощью `cudaMalloc`.
2. Матрицы $A$ и $B$ копируются из оперативной памяти (Host) в видеопамять (Device) функцией `cudaMemcpy`.
3. Запускается ядро `matrixMulKernel`. В отличие от CPU, где параллелизм строился по строкам, в CUDA создается двумерная сетка потоков (2D Grid & 2D Block). Каждый отдельный поток вычисляет строго **один элемент** результирующей матрицы $C[row][col]$, выполняя цикл из $N$ итераций.
4. Результат $C$ копируется обратно на Host.
5. Время измеряется с помощью `cudaEvent_t`, что позволяет точно замерить время работы видеокарты (включая передачу данных по шине PCI-Express), минуя задержки файлового ввода-вывода.

## 3. Условия экспериментов
* **Компилятор:** `nvcc` (NVIDIA CUDA Compiler).
* **Исследуемые объемы задачи N:** 200, 400, 800, 1200, 1600, 2000.
* **Конфигурации блоков потоков:** `8x8` (64 потока на блок), `16x16` (256 потоков), `32x32` (1024 потока).
* **Верификация:** Автоматизированная проверка результатов через Python (NumPy) успешно пройдена с допуском `atol=1e-5`. Данные типа `double` (64-бит).

### 4.3. Анализ результатов
* **Колоссальное ускорение:** По сравнению с однопоточной версией из ЛР №1 (которая на $N=2000$ занимала ~21 сек), видеокарта выполняет ту же задачу за доли секунды (~0.05 сек), что дает ускорение более чем в **100 раз**. 
* **Влияние размера блока:** Конфигурация `8x8` работает немного медленнее, так как 64 потока не позволяют полностью загрузить мультипроцессоры (SM) видеокарты (возникает недоутилизация варпов). Конфигурации `16x16` и `32x32` показывают наилучшую и практически идентичную производительность, так как кратно заполняют планировщик варпов (warp size = 32).
* **Накладные расходы шины:** На малых матрицах ($N=200$) основное время тратится не на сами вычисления, а на копирование данных `Host -> Device` и `Device -> Host` по шине PCI-Express.

## 5. Выводы
1. Разработана CUDA-программа для умножения матриц. 
2. Доказано превосходство архитектуры GPU для параллельных вычислений типа SIMT (Single Instruction, Multiple Threads). Для задач с интенсивной матричной арифметикой видеокарты на порядки превосходят центральные процессоры (OpenMP / MPI).
3. Оптимальный размер блока потоков для данной задачи составляет 16x16 или 32x32, что соответствует архитектурным особенностям планировщика NVIDIA.
